# DriveCare — local security baseline

هذا المشروع هو نسخة أولية لتطبيق ذكي يتابع حالة السيارة، سجل الصيانة، استهلاك الوقود، التنبيهات، وتقارير صحية سريعة. النسخة الحالية هي قاعدة محلية آمنة للتطوير وليست خدمة إنترنت أو أداة تشخيص معتمدة.

## الهدف

- متابعة حالة السيارة بشكل يومي
- تنبيه مبكر عند مشاكل محتملة
- جدولة الصيانة بناءً على الاستخدام
- مقارنة استهلاك الوقود بين الرحلات
- تمثيل بسيط للـ Health Score

## البنية الحالية

- Frontend: static HTML/CSS/JS app for owner dashboard and garage companion
- Backend: Python HTTP server with SQLite-backed API
- Storage strategy: local-first + summary-based data + future cloud sync
- Auth: signup/login via API token
- Vehicles: multi-vehicle support per user
- Export: JSON backup snapshot of active records

## التشغيل

```bash
python server.py
```

أو:

```bash
npm start
```

ثم افتح:

```text
http://localhost:3000
http://localhost:3000/garage
```

الخادم يستمع محليًا على `127.0.0.1` فقط افتراضيًا. لا تفتحه على الشبكة إلا بعد إضافة HTTPS، إدارة مستخدمين إنتاجية، ومراجعة أمنية مستقلة. لا تستخدم `DRIVECARE_ALLOW_LAN=1` في هذه المرحلة.

## التحقق

```bash
python -m py_compile server.py
python -m unittest discover -s tests -v
```

## ما تم تحصينه

- كلمات مرور الحسابات الجديدة تستخدم `scrypt` مع salt عشوائي؛ كلمة المرور القديمة بصيغة SHA-256، إن وجدت وصحّت عند تسجيل الدخول، تُرقّى تلقائيًا إلى الصيغة الجديدة.
- جلسات الدخول مخزنة كبصمة token في SQLite، صالحة 24 ساعة، ويمكن إبطالها بتسجيل الخروج؛ لا تُخزَّن token نفسها في القاعدة.
- بيانات السيارات، الورش، لوحة الورشة، والتصدير تتطلب تسجيل دخول، ولا توجد بيانات نموذجية عامة عبر API.
- الخادم يحتفظ بسجل تدقيق أولي للتسجيل، الدخول، والخروج.
- اتصالات SQLite تُغلق بعد كل طلب لتقليل تعارضات الملف والنسخ الاحتياطي في Windows.

## الميزات الجديدة

- تسجيل مستخدم جديد
- تسجيل دخول باستخدام token
- إدارة أكثر من سيارة داخل حساب واحد
- export بيانات JSON للنسخ الاحتياطي
- API موحد لكل App owner + garage companion
- لكل سيارة مالك واحد فقط (`vehicles.user_id`) ولا يمكن لحساب آخر إعادة تسجيلها كمالك
- المالك وحده يضيف السائقين ويمنح صلاحية اقتران جهاز OBD لمدة محددة أو يلغيها فوراً
- صلاحية السائق تنتهي تلقائياً، وتُراجع من الخادم قبل محاولة الاقتران

## الخطوة التالية

- إضافة واجهة onboarding لإنشاء السيارة والتحقق من الملكية (VIN/رمز مركبة).
- تحويل طبقة OBD إلى Android أصلي مع Foreground Service وبروتوكولات BLE/Classic/Wi-Fi محددة ومختبرة.
- تطبيق صلاحيات الورشة عند قراءة كل نوع بيانات، وليس عند إنشاء الطلب فقط.
- إضافة نسخ احتياطي مُشفّر، rate limiting، استرداد حساب، اختبارات صلاحيات شاملة، وسجل تدقيق قابل للمراجعة.
- إضافة push notifications بعد تصميم موافقات وخصوصية واضحين.

## صلاحيات جهاز OBD

اقتران السائق ليس مفتوحاً بمجرد تركيب القطعة في السيارة. يجب أن يكون السائق مرتبطاً بالسيارة، ثم يمنحه المالك صلاحية `pair` بوقت انتهاء. يحتفظ الخادم بسجل المنح والإلغاء، ولا يسمح للسائق بإنشاء أو تعديل أو إلغاء أي منحة.

هذا يتحكم في استخدام الجهاز داخل التطبيق. أما منع شخص من الاقتران بالقطعة من إعدادات الهاتف مباشرة فيتطلب أن تدعم قطعة OBD نفسها PIN أو مصادقة Bluetooth؛ التطبيق وحده لا يستطيع التحكم في اقتران Bluetooth خارج التطبيق.

## ملاحظات تصميم

- لا يتم تخزين كل قراءة OBD خام كل ثانية
- بدلاً من ذلك، يتم اعتماد summaries + alerts + thresholds
- هذا يقلل التكلفة والذاكرة ويبقي التطبيق خفيفاً على الهاتف
- لا تُستخدم قيمة `Health Score` الحالية كتشخيص أو قرار صيانة؛ هي تلخيص تجريبي حتى تصل بيانات OBD حقيقية ومعايير موثقة.
